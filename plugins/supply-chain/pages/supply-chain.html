Supply chain

Every file from another project is a risk that someone must manage. Ordinance DS lists each such file, and the check compares it with its checksum.

1

In the folder today

The build and the checks use Node.js and no package.

One test uses packages: the test with Base UI, in the folder tests/base-ui. Its three packages have exact versions, and a lock file holds their checksums. They are never part of the built site.

The linter for the scripts is in the folder tools/lint, with its own packages and its own lock file. It runs in the pipeline and on the computer of a developer. The build and the check do not use it.

2

How a file is added

  1. Get the file from its project. Compare its checksum with the value that the project publishes.
  2. Put the file in the folder third-party/.
  3. List it in third-party.json, or in the plugin.json of the plugin that uses it.
  4. Give its project, version, licence, source and SHA-256 value.
  5. Build, and then check.

The check fails for a file in third-party/ that is not listed. It also fails for a listed file that has changed.

3

The rule that this answers

The EU Cyber Resilience Act asks a manufacturer to know the components of its product. A list with checksums is the base for that.
