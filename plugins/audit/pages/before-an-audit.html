Before an audit

Most findings in an audit come from choices that were made early. This page lists the habits to start with, and how to judge a tool before you add it.

1

What this page is

This page is advice. No tool and no starter pack makes a product pass an audit. A tool can support a control, and your team must still show that the control works.

The names of tools are examples of a kind. Ordinance DS has tested only the ones that the page Supply chain lists.

3

Six questions before you add a tool

  1. Does it work under the strict security policy, with no inline code and no eval?
  2. Does it ask no other server at run time, except the ones that you have listed?
  3. Is it pinned by a lock file or a checksum, and is it in your bill of materials?
  4. Does it work without a fixed key in a file or in browser code?
  5. If it sends logs or measurements, is personal data removed before they leave?
  6. Is its licence clear and listed, and can you replace the tool later?

One answer of no is a reason to stop and write down why the tool is still needed.
