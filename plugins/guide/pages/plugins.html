Plugins

A plugin is one folder that adds pages, styles or checks. The build compiles every plugin in, and nothing is loaded while a page runs.

Write a plugin

  1. Make a folder in plugins/. Its name is the id of the plugin.
  2. Write plugin.json with the id, a title, a purpose, the permissions and the pages.
  3. Write each page as a fragment: the body of the page, without the menu.
  4. Write help.json with the help of each page.
  5. Build, and then check.

The plugin example is the smallest plugin that works. Copy its folder to start. Its page stands under this page in the menu.

A page can stand under another page. Its entry in plugin.json then has under with the file name of the page above.

When the page above is not built, the page becomes an item of its own group.

3

Permissions

A plugin asks for exactly what it uses. The check refuses a permission that is missing, and a permission that is not used.

4

The rules for a plugin

  • A plugin is complete in one folder. Every file in the folder is named in plugin.json.
  • A page links only to pages of its own plugin.
  • The site builds and passes without the plugin. The check proves it for every plugin.
  • A plugin is compiled in when the site is built. It is never fetched or loaded while the site runs.

The idea that every part is a plugin comes from two open projects, DeepSeek Harness and Cordis. Ordinance DS differs in the last rule of the list.
