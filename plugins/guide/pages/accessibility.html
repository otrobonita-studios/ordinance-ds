Accessibility

The accessibility rules are built into the tokens and the parts. The check measures what a script can measure.

1

Contrast

Text must reach a contrast of 7:1, and the edge of a control 3:1. These are criteria 1.4.6 and 1.4.11 of WCAG 2.2.

2

Keyboard and structure

  • The first link of a page skips to the content (2.4.1, Bypass Blocks).
  • The focus has a visible outline (2.4.7, Focus Visible).
  • The menu and the help open with the keyboard (2.1.1, Keyboard).
  • A button is at least 24 px high (2.5.8, Target Size).
  • A page says its language and has a title (3.1.1 and 2.4.2).
  • Headings come in order, and a table has a caption (1.3.1, Info and Relationships).
  • A status has words, and a link is underlined (1.4.1, Use of Color).

The check reads every built page for the points below. The file scripts/a11y.mjs holds them.

  • Every link, button and picture has a name, and a link says where it leads (4.1.2 and 2.4.4).
  • Every form control has a label, and a group of controls has a legend (3.3.2, Labels or Instructions).
  • Every reference, such as aria-labelledby, names an element that exists (1.3.1).
  • Every head cell of a table has a scope (1.3.1).
  • The keyboard follows the order of the page: no tabindex above 0, and no autofocus (2.4.3, Focus Order).
  • The page does not stop zoom, and it does not reload by itself (1.4.4 and 2.2.1).

The browser test then measures what only a browser knows.

  • The browser gives every control a name in its accessibility tree (4.1.2).
  • Every control is at least 24 px wide and high (2.5.8).
  • The Tab key reaches every control. Each one shows its focus, and nothing covers it (2.4.7 and 2.4.11).
  • Every page fits a screen of 320 px without scrolling sideways (1.4.10, Reflow).
  • With wider spacing of lines, letters and words, no text is cut off (1.4.12, Text Spacing).
  • In the forced-colours mode of the system, a control keeps its edge and the focus keeps its outline.
3

State as attributes

A part shows its state with an attribute, such as aria-current or data-tone. Component frameworks set state in the same way.

A test proves it with Base UI, a set of React components without styles. It is in the folder tests/base-ui.

  • A Base UI switch, tab and button take the class names of Ordinance DS.
  • They set data-checked, data-disabled and aria-selected, and the stylesheet has a rule for each.
  • On a server, Base UI writes style attributes, which the security policy blocks. So a product renders these parts in the browser.

The packages of the test are in its own folder. The site and the build do not use them.

4

What a script cannot see

A script cannot judge whether a text is clear, or whether an order makes sense.

A person must still test each product with a keyboard and with a screen reader.
