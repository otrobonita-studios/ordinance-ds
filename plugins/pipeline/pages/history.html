History

The history of a repository is a record of every change. A review of a regulated product reads that record, so it must be kept with care.

1

What the record must answer

A reviewer picks a change and asks four questions. The history and the code host must answer them without the help of a person.

  • What changed, and why?
  • Which person is responsible for it?
  • Who approved it, and was that a second person?
  • Which tests passed before it was merged?

The history answers the first two questions. The code host answers the last two, and the next clause lists its settings.

2

The main branch

These are settings of your code host. Ordinance DS cannot set them, and it cannot check them.

3

A commit

  • A commit holds one change that has one reason. A reader can then review it alone, and undo it without losing other work.
  • Each commit builds and passes the check by itself. A reviewer can then stop at any commit.
  • A change of names or a move of files is its own commit, apart from a change of behaviour.
  • The first line of the message says what changed, in under 72 characters. The lines after it say why.
  • A commit names the person who is responsible for it. It names no tool and no AI agent, whatever helped to write it.
  • A commit holds no secret, no personal data and no path of a computer.
  • A mistake in a published commit is corrected with a new commit. The old one stays.
4

A pull request

A pull request is read by a person, and often first by a program. Both read better when it is small and says how to read it.

  • One pull request has one purpose, and it is small enough to read in one sitting.
  • The description says what changes, why, and what could go wrong.
  • It lists the commits in the order to read them, and says where to look hardest.
  • It says what was not done, and what could not be tested. A reviewer cannot see what is missing.

The file AGENTS.md has the full rules, and the folder .github has the template.

5

The history check

A file that is corrected today is still in the history as it was. So one command reads every commit.

node scripts/history-check.mjs

Run it before the first push, because a published history cannot be taken back. After that, run it before each release.

The command needs git. It is not a part of the rules on the page Checks, which read only the files of today.

6

The address of an author

Every commit carries the name and the email address of its author. With the first push, they are public for good.

A code host can give each person an address that hides the real one. Set it in git before the first commit.
